# Repository instructions

## Lineup artwork (every AI editor)
When the owner says "check roster lineups" or "check rosters", check the current rosters, complete needed artwork updates, and push them to main for publication. Do not stop after reporting missing artwork.
Read `docs/lineup-artwork-protocol.md` before EVERY player lineup artwork generation or edit, including crutches and all alternate poses. It is the only workflow: generate ONCE (Justin Jefferson reference + official headshot) → `python3 scripts/fit-player-head.py GENERATED.png OUT.webp` (sets head size, packages the 850px WebP) → catalog → publish. The owner forbids publishing checks, test passes for artwork-only updates, proof/comparison files, percentage reports and approval rounds. Older head-size targets, prompt-only constructions and measurement loops in this repository's history are superseded.

Before ANY roster lineup code or styling update, read `assets/team-photos/STYLE_GUIDE.md` and preserve all original requirements. Resting figures use relative real heights; selected figures intentionally share one enlarged size. Run the lineup checks before publishing code or styling changes (never for artwork-only updates).

Before ANY manager avatar or figure update, read `assets/MANAGER_ARTWORK_RULES.md`. HARD RULE: NEVER cut out, paste, composite, fit, or independently resize a separate head onto a body. Never use jaw masks, neck patches, or head-fitting scripts to assemble manager figures. Generate each complete pose as one coherent image, with the head, naturally shaded neck, collar, and body drawn together. Use approved portraits for identity and approved whole figures for pose, clothing, build, head-to-body scale, and framing. This owner correction supersedes all older instructions to preserve original body pixels or replace only the head. If the owner asks to see artwork before publishing, show the complete set and wait for approval.

Before ANY manager or player image update, read `assets/ARTWORK_PROPORTIONS.md` and `assets/artwork-proportions.json`. Use the named original image templates; do not guess proportions from prose. Preserve visible shaded necks. Manager artwork keeps its own rules; player figures are finalized by `scripts/fit-player-head.py` with no inspection or approval round.

Before ANY change to the NFL weekly schedule under the top carousel or its game page, read `docs/game-center.md`: `scripts/game-center.js` replaces `renderNFLWeekSchedule`, `nflCardHTML` and `nflUpdateScoreCard`, so edits to those functions in index.html do nothing.

Site updates reach open copies (Home Screen apps) through `scripts/app-update.js`: `scripts/prepare-site.mjs` stamps each build with its commit (`<meta name="hj-build">` and `version.json`). Keep both when changing the build.

Before ANY top-carousel / Wire card update, read `docs/wire-card-rules.md` and `docs/wire-live.md`. Preserve shared sizing, expansion, scrolling, gestures and refresh behavior. An approved card design does not waive those rules. Compare desktop and mobile cards against an existing ordinary card before publishing.

## Hard rule: identify players by ESPN player id — owner instruction November 2
Every feature that links, merges or compares player data (stats, fantasy points, projections, ownership/managers, injuries, depth charts, headshots, profiles, game logs) must match players by their ESPN player id (D/ST: -16000 minus the NFL team id). Names are for display.
- When both sides carry the ESPN id, match on the id only. If the id is not in the other set, that is the answer (e.g. an ESPN id that is on no league roster is a free agent); do not then try the name, because two players can share a name.
- When a source has no ESPN id (play-by-play injury notes such as "BUF-J.Cook was injured", Vegas projection rows, feeds keyed by their own ids), map it to the ESPN id once: by a published id crosswalk when one exists (e.g. nflverse espn_id), otherwise by name within the smallest set (the players on that play, then that team's roster, with position). From then on use the ESPN id. Say in a code comment why that source needs the mapping.
- Do not change existing site features just to enforce this rule; apply it to new and edited code, and fix an existing name match only where it causes a wrong result.

## Hard rule: names are never cut off (players Nov 2; managers and teams Nov 11)
Never truncate a player's, manager's or team's name with "..." or clip it with overflow, anywhere on the site. Long player names wrap between words; manager names stay on one line ("NATHAN T" is never split), so give them the room they need (e.g. the Standings table and the recap's Movers and Position battles cards were widened for this). `styles/full-names.css` (loaded last) lifts the old ellipsis rules on every name element; add any new name element that could run long to it, and never give a name `text-overflow:ellipsis`. Deliberate short forms already used by a design (e.g. "L. Jackson" in leaders and play chips, a last name in compact table cells) are not truncation and stay as they are.

## Hard rule: side bets in the Wire carousel — owner instruction November 8
A side bet for the week being played (or an upcoming week) keeps its "Side Bet" place near the front of the carousel. Once its week is over (that week's recap is showing), its card goes after every recap card of that week, never at the front. `scripts/side-bet-order.js` enforces this for every bet after the carousel sorts its sections; a new bet only has to give its card its week: `{section:'sidebet',week:N,html}` (a card without `week` is read from its "Week N · …" tag). Do not place a bet card yourself, do not give it another section, and do not edit `HJ_WIRE_ORDER` for a bet. Test: `scripts/test-side-bet-order.mjs` (run by the publish workflow).

## Hard rule: circular player headshots
Every circular NFL player avatar must follow the existing roster and Wire player avatar treatment: use `object-fit: cover` with centered positioning so the jersey/bust reaches the circle's bottom edge. Never use `object-fit: contain` for a human headshot in a circle; it exposes a flat rectangular bust edge and an empty crescent underneath. Preserve the established avatar size, proportions and surrounding layout. Apply this rule to new cards, expanded cards, mobile and desktop. NFL team/DST logos are the exception: retain `object-fit: contain` so the full logo remains visible. Reuse the existing player-avatar styling instead of introducing a different crop.

## Crutch artwork stance — owner correction October 14
Before generating or editing any status artwork, open an existing approved image of that SAME status. For crutches, use `assets/team-photos/players/4047646-crutches-v1.webp` as the pose reference in addition to the player's regular artwork and official headshot. Match the established upright standing pose: BOTH legs straight, BOTH normal cleats planted on the same baseline, with one silver underarm crutch on each side. Preserve the regular lower body and add crutches; only adjust hands to hold the grips. Never lift a foot, bend a knee backward, invent a hopping/one-leg stance, cast, boot or missing limb unless the owner explicitly requests it. The October 14 Montgomery, Deebo Samuel, Shipley and Henderson crutches-v1/v2 poses were rejected; do not use them as references. Their crutches-v3 replacements restore the established pose. Read and use existing section artwork BEFORE creating new artwork. The no-publishing-checks instruction does not waive this preparation rule; no new publication gate or proof artifact is required.
